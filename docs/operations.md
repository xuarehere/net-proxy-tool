## 找到正在使用的配置

Web、CLI 和 SDK 共享网关配置，按以下顺序查找文件。要让多个入口使用同一个自定义配置，请给它们设置相同的绝对路径。

1. 环境变量 `NET_PROXY_CONFIG` 指定的文件。
2. 程序目录中已有的 `config.json`，用于兼容旧安装。
3. 当前用户的默认配置文件。

| 系统 | 默认路径 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\net-proxy-tool\config.json` |
| macOS | `~/Library/Application Support/net-proxy-tool/config.json` |
| Linux | `$XDG_CONFIG_HOME/net-proxy-tool/config.json`，未设置时为 `~/.config/net-proxy-tool/config.json` |

第一次保存网关时写入配置。配置旁的 `data/` 存放 `console.log`、节点操作审计日志和启动器状态。`instance.json` 含停止当前实例所需的令牌，应与配置文件一样保密。配置文件损坏时，先备份原文件并修正 JSON，再启动。

**升级旧安装** · 停止旧服务，备份自己的配置，在新目录解压发布包。可以将 `NET_PROXY_CONFIG` 指向备份之外的正式配置文件。已有网关和节点会被读取；只启动控制台不会重新向节点下发开关。单次 CLI 可用 `--gateway HOST:PORT` 或 `NET_PROXY_GATEWAY` 覆盖当前网关。用完后移除临时覆盖即可回到保存的设置。

## 按使用范围选择入口

| 操作 | 适用场景 |
| --- | --- |
| CLI / `ProxySession` | 一个本机命令或一段 Python 代码。SDK 的环境变量在同进程线程间共享。 |
| 拓扑 → 远程 SSH | 目标 Linux 系统已有 SSH 服务，需要为指定账号配置多个工具。控制端需要 `ssh`；先验证该账号的常规 SSH 登录。 |
| 拓扑 → 映射端口 SSH | 容器内运行 SSH 服务，填写宿主机地址及实际映射端口，登录的是容器账号。 |
| 拓扑 → 经宿主机访问 Docker | 宿主机账号能使用 Docker，填写可登录的宿主机和精确的容器名。容器内需提供 POSIX shell。 |

先添加目标和网关绑定，执行单节点预检，再在目标节点切换并测试。预检和测试结果位于操作界面，批量切换应逐项查看结果。在远程节点上使用 `127.0.0.1` 会访问该节点自身。远程客户端需要能访问网关的实际网络地址。

远程开关可修改目标账号的 curl、wget、pip、Git 和 shell 配置。使用 root 时还可能修改目标的系统级配置。v1.4 在目标账号的 `~/.local/state/net-proxy-tool/` 保存快照。关闭操作如报告目标文件被人工修改，请对照快照合并，自行编辑过的内容需要保留。旧版产生、缺少原始快照的文件同样需要人工复核。

## 通过 Docker Compose 启动

在有 Docker 和 Compose 的机器上，从源码目录运行下列命令。控制台默认发布至宿主机回环地址的 8899 端口，配置保存在命名卷内。

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=80
```

在宿主机浏览器打开 `http://127.0.0.1:8899/`，停止时执行 `docker compose down`。容器内的 `127.0.0.1` 是容器自身。填入从容器可达的网关地址，并确认代理允许来自该网络的连接。需要使用其他宿主机端口时，在启动 Compose 前设置 `NET_PROXY_HOST_PORT`，并使用相应 URL。

## 根据症状定位

| 现象 | 下一步 |
| --- | --- |
| 双击后没有显示页面 | 检查是否已完整解压、是否选对架构；从终端运行启动器查看错误。若已打印 URL，手动打开。 |
| 8899 被占用 | 使用 8900 等空闲端口启动。若是本配置的实例，先用同一启动器的 `--stop` 停止。 |
| 控制台能打开，但网关测试失败 | 核对代理监听地址和 HTTP/混合端口。TCP 不通时排查服务、监听接口及防火墙。仅 TCP 可达时，检查代理协议、上游路由和目标站点。 |
| 收到 HTTP 407 | 代理要求认证。当前网关表单接受主机和端口，请使用你有权访问的 HTTP 转发入口。 |
| HTTPS 证书错误或目标返回 403 / 429 | 确认目标 URL 与证书链，检查目标站点访问策略、限流和代理日志。 |
| 节点显示不可达 | 先从控制端验证 SSH 主机、端口、用户和密钥；宿主机模式还需检查 Docker 权限及容器名。 |
| 新版本读不到已保存的网关 | 按上述优先级确认正在使用的配置，尤其检查旧程序目录、启动账号和 `NET_PROXY_CONFIG`。 |

`GET /api/health` 返回当前服务标识、版本、PID 与状态，可用于判断启动是否成功。网关是否真正可用，需在控制台向指定目标发送一次代理请求。
