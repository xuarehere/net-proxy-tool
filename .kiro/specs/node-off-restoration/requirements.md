# Requirements Document: node-off-restoration

## Introduction

Operators reported two regressions:
1. Under light OS/browser color schemes, the expandable "Worker node tunnel and proxy wizard" header banner (`#advanced-wizard .wizard-header-banner`) and stepper pipeline retain hardcoded dark navy backgrounds while inheriting dark light-mode text, making the heading and steps unreadable.
2. When disabling proxy settings (`action="off"`) on remote Linux SSH nodes or Docker containers (`docker_host` or `ssh`) that previously received `net-proxy-tool` settings (including legacy v1.3 / `5036f30f` `# --- NET-PROXY-TOOL-START ---` blocks, `~/.net-proxy-switch.sh`, `# Generated by net-proxy-tool` `/etc/profile.d/*`, `# net-proxy-tool` lines in `/etc/environment`, or `/etc/*` configs), switching off either restored the proxied legacy file as "original baseline", skipped remote cleanup via `_node_restored_baseline`, or left container/system files untouched—allowing proxied egress (such as reaching external targets) to silently continue after the node showed disabled.

## Requirements

### Requirement 1: Readable Wizard Contrast Across Color Schemes
**User Story:** As an operator opening the console on light or dark themes, I want high-contrast foreground text on every wizard banner, stepper bar, toolbar and feedback panel.
#### Acceptance Criteria
1. `.wizard-header-banner`, `.stepper-pipeline`, `.live-feedback-box`, `.table-toolbar` and `.search-input:focus` SHALL use CSS custom properties updated under `@media (prefers-color-scheme: light)`.
2. Under both light and dark color schemes, heading text, subtitle text and step pills in `#advanced-wizard` SHALL remain clearly legible against their background.

### Requirement 2: Clean Removal of Tool-Managed & Legacy Proxy Settings on Disable
**User Story:** As an operator disabling a managed Linux node or Docker container, I want every proxy setting created by any version of `net-proxy-tool` to be removed cleanly so traffic no longer traverses the disabled proxy.
#### Acceptance Criteria
1. WHEN `action="on"` creates or updates a snapshot, any pre-existing `net-proxy-tool` markers (`# --- NET-PROXY-TOOL-START ---` .. `# --- NET-PROXY-TOOL-END ---` blocks and `# net-proxy-tool` tagged lines) SHALL be stripped from the saved restoration baseline while preserving all user-authored non-tool lines and file permissions.
2. WHEN `action="off"` executes, `web/provision.sh` SHALL remove `# --- NET-PROXY-TOOL-START ---` blocks from user profiles, `~/.net-proxy-switch.sh`, and `# net-proxy-tool` tool-tagged entries even if an older snapshot contained legacy markers or no `$state` directory existed (legacy cleanup), while preserving all genuine non-tool operator settings.
3. WHEN running as `root` (`id -u = 0`) or with passwordless `sudo -n` (or for Docker container targets), `action="off"` SHALL also cleanly restore/strip `/etc/profile.d/net-proxy.sh`, `/etc/profile.d/net-proxy-switch.sh`, `# net-proxy-tool` lines in `/etc/environment`, `# --- NET-PROXY-TOOL-START ---` blocks in `/etc/bash.bashrc` and `/etc/profile`, and tool-managed entries in `/etc/curlrc`, `/etc/pip.conf`, `/etc/gitconfig` and `/etc/apt/apt.conf.d/99net-proxy`.
4. Genuine non-`net-proxy-tool` third-party proxy settings (written manually outside tool markers) SHALL still be preserved as the operator's baseline.

### Requirement 3: Container Coverage (Login, Non-Login & PAM Environments) Without Host/Sibling Pollution
**User Story:** As an operator using `docker_host` or SSH Docker nodes, I want `on` to work across interactive/non-interactive shells and `off` to disable all of them inside that container only.
#### Acceptance Criteria
1. WHEN `action="on"` runs on a Docker node (`docker_host` or `os_type="docker"` with root privileges), provisioning SHALL manage container-scoped `/etc/profile.d/net-proxy.sh`, `# net-proxy-tool` lines in `/etc/environment`, and `/etc/curlrc` alongside `/root/*` and system pip/git/apt files—all snapshotted atomically under the state directory.
2. WHEN `action="off"` runs, those files SHALL be restored or removed inside the target container only; the Docker host and sibling containers MUST remain untouched.

### Requirement 4: Honest Post-Disable Verification (No False-Clean Skip)
**User Story:** As an operator, I want `off` to never skip cleanup or falsely report a clean direct node if proxy variables matching the disabled gateway remain active.
#### Acceptance Criteria
1. `apply_node_proxy(target, "off", cfg)` SHALL NOT skip executing `provision.sh off` via `_node_restored_baseline` when `current_state != "disabled"`, when `legacy_residual` is detected, or when `proxy_variables` still match the disabled gateway.
2. IF post-`off` verification detects residual proxy variables matching the disabled gateway (`matches_selected_gateway`) or unremoved tool markers (`legacy_residual`), `apply_node_proxy` SHALL report `verified=False` (`returncode=1`, `managed_state="conflict"` / clear error) instead of silently marking the node cleanly disabled.
