Scope and restoration
  • After it is enabled, curl, wget, pip and Git in the target account can read their own proxy settings. Programs that depend on shell variables should be checked in a new terminal.
  • When the managed state stops, the tool restores the configuration from the snapshot taken before it was enabled. A proxy that already existed may still apply, so repeat the request with a plain curl to check the current path.
  • The container mode runs the configuration script inside the selected container. Running it as root can change system-wide settings on the target; when the restoration conflicts, check the files on the target.

Project home · First run guide · Remote access and restoration

One command on Windows

Open PowerShell in the extracted folder of the portable archive. The script uses the bundled Python and sets the proxy for this one curl command.

.\bin\with-proxy.cmd curl.exe -I https://www.google.com/
One command on Linux or macOS

Run it in the extracted folder of the portable archive. Bash and curl must already be installed. The source archive also needs Python 3.8 or newer.

./bin/with-proxy curl -I https://www.google.com/
Python SDK

Save the code as check_proxy.py in the root of the package and run it from the same directory. On Windows use .\runtime\python.exe check_proxy.py, on Linux or macOS use ./runtime/bin/python3 check_proxy.py. The proxy variables of the current process are restored when the block exits.

from urllib.request import urlopen
from sdk import ProxySession

with ProxySession():
    with urlopen("https://www.google.com/", timeout=10) as response:
        print(response.status)
One command inside a container

Run it in a Bash terminal with the Docker CLI and access to the container. Replace app-container with the name of a running container that has curl installed. The proxy address saved in the console must be reachable from the container; 127.0.0.1 points at the container itself.

./bin/with-proxy-docker app-container curl -I https://www.google.com/

Keep a proxy enabled for a remote account

Register a Linux node or a container in the node management view with its SSH user, host and real port. A Windows controller uses an OpenSSH key. The Docker host mode also needs that account to run docker exec. Save it and run the pre-check first.

The tool and shell configuration is written only when you enable it explicitly. The target is the selected account or container, and running as root can also change system-wide settings on the target. Stopping restores the snapshot. When the file was edited by hand or an older version left no snapshot, read the notice and check the backup.
